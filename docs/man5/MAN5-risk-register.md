# 风险登记册（MAN.5）

本文件合并了原先分开记录的「风险表」和「待确认的事实」。两者本是同一事物的两面：
**一个尚未核实的事实，和「若它不成立会怎样」的后果**。分开记录只会造成重复和漂移。

风险按**失败后果的严重程度**排序，而不是按发生概率。排在最前的两条有一个共同特征：
**失败时会给出看似合理的错误数据**。被悄悄误导比明显的失败危险得多，
因此它们排在只会让工具变慢或变浅的风险之前。

条目通过把「状态」改为**已关闭**来退役，并写明关闭依据，**不要删除**。
保留历史能说明结论是如何变化的。

## 开放的风险

### R-001 杜邦线信号完整性不足

| 字段 | 内容 |
| --- | --- |
| 未核实的事实 | 本套接线的实际边沿速率上限 |
| 影响 | `SYS-002` 的有效性 |
| 后果 | 边沿振铃被判成多次跳变，解码出**看似合理的错误字节** |
| 缓解 | 优先用零成本手段：两个 GND 都接、信号与地双绞、闲置引脚驱动低电平作伪地。不足时可购置带地线的测试夹或屏蔽排线，`STK-004` 允许购置配件 |
| 确认时机 | 阶段 1，用已知内容的 SPI 对照 |
| 状态 | **开放** |

⚠️ 本风险有一个特殊之处：**本系统对它是半盲的**。100 MSa/s 意味着窄于 10 ns 的
脉冲可能完全不被采到，而振铃产生的毛刺很可能就在这个量级。因此判断信号完整性
不能只依赖本系统的采集结果，还应结合解码是否出错，必要时用示波器交叉验证。

### R-002 UART 无流控导致静默丢字节

| 字段 | 内容 |
| --- | --- |
| 未核实的事实 | 高波特率下主机能否持续取走数据；Basys 3 是否引出 RTS/CTS |
| 影响 | `SYS-006` `SYS-007` `SYS-015` |
| 后果 | 丢一个字节后全部错位，**同样是看似合理的垃圾** |
| 缓解 | SUMP 原生支持 XON/XOFF 流控。E3 必须在发送期间保持接收通路活跃，随时响应暂停 |
| 确认时机 | 阶段 1b，用已知合成数据全速传输并核对 |
| 状态 | **开放**，缓解手段已确定 |

### R-003 被测板上控制线无可用测试点

| 字段 | 内容 |
| --- | --- |
| 未核实的事实 | SR150 的 `HELIOS_CE`、`HELIOS_GPIO5_HOST_INT` 等控制线在实物板上是否可接入探针 |
| 影响 | `STK-002` |
| 后果 | 只能采集 SPI 四线，看不到中断时序，回答不了「主机为什么此刻发起传输」 |
| 缓解 | 无法从 FPGA 侧解决，取决于被测硬件 |
| 确认时机 | 实际接线时 |
| 状态 | **开放** |

### R-004 BRAM 实际可用比例低于估计

| 字段 | 内容 |
| --- | --- |
| 未核实的事实 | 布线后可用于采集缓冲的 BRAM 比例（估计约 200 KB／225 KB） |
| 影响 | `SYS-003` |
| 后果 | 采集深度缩水 |
| 缓解 | 下调深度；或提前引入游程编码 |
| 确认时机 | 阶段 1 综合后查看资源报告 |
| 状态 | **开放** |

### R-005 Pmod 串联电阻拖慢边沿

| 字段 | 内容 |
| --- | --- |
| 未核实的事实 | Basys 3 的 Pmod 口串联保护电阻阻值（估计 200 欧） |
| 影响 | 加剧 R-001 |
| 后果 | 与线缆电容构成低通，进一步限制可捕获的边沿速率 |
| 缓解 | 无法更改，只能在接线上补偿 |
| 确认时机 | 查阅 Basys 3 reference manual 即可 |
| 状态 | **开放** |

## 已关闭的风险

### R-006 PulseView 与本设备的互操作细节

| 字段 | 内容 |
| --- | --- |
| 原始担忧 | SUMP 完整命令字列表与各自长度、metadata 应答格式、flags 对每样本字节数的影响均未知。命令长度判断错误会导致永久失步；字节数契约不符会导致数据错位 |
| 关闭依据 | 2026-08-12 从 libsigrok 的 `ols` 驱动源码核实全部四项，规格记入 `../sys3/SYS3-system-architecture.md` 的 I4 一节 |
| 主要发现 | **命令长度可由 bit7 直接判断**，无需查表，这消除了失步风险的主要来源。ID 应答为 4 字节 `"1SLO"` 或 `"1ALS"`。metadata **可以不实现**，驱动会退回通用默认值。每样本字节数等于 flags 中启用的通道组数，8 通道即 1 字节 |
| 残留 | metadata 中「采样存储字节数」等键的具体值未逐一核实，仅确认了编码规则。若决定实现 metadata，需再核对一次 |
| 状态 | **已关闭** |

### R-007 后续目标设备的 SPI 速率可能远高于首个验证目标

| 字段 | 内容 |
| --- | --- |
| 原始担忧 | UWB 收发器的主机接口为满足吞吐通常跑得较快，若显著高于 10 MHz，当前探针方案与 100 MSa/s 采样率均不足，需引入屏蔽探头和 `ISERDESE2` 过采样 |
| 关闭依据 | 2026-08-12 查阅生产固件 `Nolo-Firmware/mk-nolo-firmware`，确认 QN9090 与 SR150 之间为 **8.000 MHz、SPI Mode 0**，与首个验证目标一致 |
| 残留 | 8 MHz 是 QN9090 的能力上限。若今后主机换成基于 nRF52840 的 Raytac 模组（SPIM3 可达 32 MHz），需重新评估 |
| 状态 | **已关闭** |

### R-008 SUMP 协议无法满足上传速率与完整性要求

| 字段 | 内容 |
| --- | --- |
| 原始担忧 | SUMP 数据阶段是无格式裸流，无校验；且波特率可能被限制在 115200，导致 `SYS-007` 的 3 秒指标达不到 |
| 关闭依据 | 2026-08-12 核实：SUMP 命令集包含 `0x11` / `0x13` XON/XOFF 流控，可**预防**丢失（虽然确实没有校验机制）；libsigrok 的 `ols` 驱动中 115200 只是缺省值，可通过 `SR_CONF_SERIALCOMM` 覆盖，且 PulseView 的连接对话框直接提供波特率下拉框，其中含 921600 |
| 影响 | 本项因此取消了自研上传协议和自研上位机，系统元素由四个减为三个 |
| 状态 | **已关闭** |
