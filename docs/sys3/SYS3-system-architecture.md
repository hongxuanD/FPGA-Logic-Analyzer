# 系统架构设计（SYS.3）

把 `../sys2/SYS2-system-requirements.md` 中的系统需求分配到具体元素上，
并定义元素之间的接口。

本层只到**系统元素**的粒度。FPGA 内部如何划分模块属于 SWE.2，不在本文件。

右侧对应 **SYS.4 系统集成测试**：测的正是本文件定义的接口。

## 系统边界

系统包含两个可编程逻辑元素和一段物理接线。**上位机软件不在系统内**——
PulseView 承担全部波形显示与协议解码职责。

```text
┌─ 系统边界 ─────────────────────────────┐
│                                         │
│  [E1 探针与接线] → [E2 采集通路] ↔ [E3 控制与通信] ─┼─→ [PulseView]
│                                         │    UART      （外部）
└─────────────────────────────────────────┘
   ↑
[被测设备]（外部）
```

### 为什么不自研上位机

早期草稿曾规划一套自研上传协议和配套的上位机工具，理由是 SUMP 缺少流控与
完整性机制、且波特率受限。**两条理由经查证均不成立**：SUMP 支持 XON/XOFF，
波特率在 PulseView 的连接对话框中可直接选择。

去掉自研协议后，系统少了一套需要设计、实现、测试和维护的接口，
`SYS-015` 由 SUMP 的流控满足，波形显示由 PulseView 承担。

**退路**：若今后发现 sigrok 的 `ols` 驱动存在无法绕开的缺陷
（已知其 RLE 处理有互操作问题），可以自行编写一个数十行的 Python SUMP 客户端。
那属于工具，不进入系统架构。

## 元素划分

FPGA 子系统在本层拆成两块，因为**两者的变更驱动力不同**：
采集通路随被测信号特性变化（采样率、通道数、触发方式），
控制与通信随上位机接口变化（协议、波特率）。
在本层画出这条界线，SWE.2 才有依据把上传协议做成可替换的。

| 元素 | 性质 | 职责 |
| --- | --- | --- |
| **E1 探针与接线** | 物理 | 把被测信号引至 Pmod，提供地回流 |
| **E2 采集通路** | 可编程逻辑 | 输入同步、按配置采样、触发判定、循环缓冲与触发前保留 |
| **E3 控制与通信** | 可编程逻辑 | SUMP 命令解析、数据上传、UART 收发与流控、板上状态显示 |

各元素**不负责**的事同样需要写明，否则职责会在实现时漂移：

- **E2 不知道任何协议。** 它既不认识 SPI，也不认识 SUMP，
  只处理「按什么条件触发、保留多少样本、按顺序交出去」。
- **E3 不知道缓冲的内部结构。** 环形缓冲的绕回、触发前后的分界由 E2 处理，
  E3 只按顺序取样本。这样把 BRAM 换成 DDR 时 E3 不受影响。

## 接口定义

| 编号 | 接口 | 两端 | 类型 |
| --- | --- | --- | --- |
| I1 | 被测信号接入 | 被测设备（外部） ↔ E1 | 电气 |
| I2 | 探针接入 | E1 ↔ E2 | Pmod 引脚，3.3V LVCMOS，纯输入 |
| **I3** | **采集控制与读出** | **E2 ↔ E3** | **FPGA 内部** |
| **I4** | **串行链路** | **E3 ↔ PulseView（外部）** | **UART 上的 SUMP 协议** |

### I1：被测信号接入

被测设备的数字信号，3.3V 逻辑电平。**本系统对被测电路只读，不驱动任何电平**
（`SYS-011`）。地回流由 E1 提供，接线要求见 `../../PROJECT_CONTEXT.md`。

### I2：探针接入

Pmod 引脚，配置为输入，3.3V LVCMOS。所需信号数量为 6 至 7 路
（SPI 四线加 SR150 的控制线），`SYS-001` 要求的 8 通道留有余量。

### I3：采集控制与读出

三个方向：

| 方向 | 内容 |
| --- | --- |
| 配置 E3 → E2 | 采样率分频、触发值、触发掩码、触发前保留比例、启动与停止 |
| 状态 E2 → E3 | 当前状态（空闲／等待触发／已触发／已存满）、已采样本数、触发位置 |
| 数据 E2 → E3 | 按顺序读出样本 |

**数据方向采用线性化的顺序流**，而非随机访问。

E2 对外呈现的是一条按时间排列的样本序列，从最早保留的那个样本开始。
环形缓冲的绕回、触发前后段的拼接，全部在 E2 内部消化。E3 看到的是一条直线，
**完全不知道存储是环形的**，因此把 BRAM 换成 DDR、或今后加入游程编码，
都不影响 E3。触发位置作为状态告知 E3，而不是让 E3 从地址推算。

⚠️ **已知的简化**：本接口不支持只上传一部分样本。当前深度下全部上传约需 1 秒，
没有部分上传的需求。若今后换用容量大得多的存储（如 DDR 的一秒量级），
需要给 I3 增加「从第 N 个样本开始」的定位能力。**这是有意的简化，不是遗漏。**

### I4：串行链路

**协议：SUMP**，由 sigrok 的 `ols` 驱动（在 PulseView 中显示为
`Openbench Logic Sniffer & SUMP compatibles`）驱动。

| 参数 | 值 | 依据 |
| --- | --- | --- |
| 波特率 | **921600**，实现为 generic 参数 | PulseView 下拉列表中可直接选择，无需手工输入。100 MHz 分频比 108.5 取整后误差 0.47%，远在 UART 容限内。传 100 KB 约 1.09 秒，满足 `SYS-007` |
| 格式 | 8N1 | SUMP 要求 |
| 流控 | **XON/XOFF**（`0x11` / `0x13`） | SUMP 原生支持，用于满足 `SYS-015` |

**流控对 E3 的约束**：发送样本期间必须保持接收通路活跃，随时可响应 XOFF 暂停、
XON 继续。这一点在 SWE.2 中必须落实，否则高波特率下主机来不及取走数据即丢字节。

**波特率若要改为 1000000**（100 MHz 整数分频，零误差），需要在 PulseView 的
波特率框中手工输入。当前不采用，因为 921600 已满足需求且操作更简便。

## 可替换点

架构中有意保留的可替换位置。**每一处都对应一个已识别的可能变化**——
没有明确动机的地方不做抽象。

| 可替换点 | 位于 | 动机 |
| --- | --- | --- |
| 存储后端 | E2 内部 | BRAM 换 DDR，若今后更换开发板。I3 的线性化顺序流已经把存储细节封在 E2 内 |
| 触发判定逻辑 | E2 内部 | 组合匹配扩展为串行模式匹配。**这是全系统唯一与协议相关的部分** |
| 上传协议 | E3 内部 | 目前只有 SUMP。若 sigrok 出现无法绕开的问题，需要能换成自定义协议 |

## 动态行为

系统的运行状态由 E2 维护，通过 I3 报给 E3，再由 E3 显示在板上（`SYS-008`）。

```text
        上电 / 复位
             │
             ▼
        ┌─────────┐   收到 Run 命令
        │  空闲   │───────────────────┐
        └─────────┘                   ▼
             ▲                   ┌─────────┐
             │                   │ 等待触发 │
             │                   └─────────┘
             │                        │ 触发条件命中
             │                        ▼
             │                   ┌─────────┐
             │                   │ 采集中  │
             │                   └─────────┘
             │                        │ 采满设定的样本数
             │                        ▼
             │                   ┌─────────┐
             └───────────────────│ 上传中  │
                 上传完毕         └─────────┘
```

阶段 1 尚无触发功能，「等待触发」状态直接穿过。收到复位命令（`0x00`）时
从任何状态回到空闲。
